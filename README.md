# Бронь стёкол — ALL IN

Калькулятор стоимости бронирования стёкол, раскроя плёнки и заказ-нарядов.
Статическое приложение для GitHub Pages, устанавливается на телефон как PWA.

## Разделы приложения

Нижняя панель переключает «Заказ», «Расчёт», «Раскрой», «Документы» и «Настройки».
На телефоне стёкла и история документов показаны карточками. Итог расчёта
выведен первым; подробности, тарифы и округление раскрываются по нажатию.
Материалы, оплата мастеру, реквизиты и Яндекс Диск находятся в настройках.
Переключение разделов не изменяет расчёт и не использует адресный фрагмент,
чтобы ссылки с размерами и импортом продолжали работать.

Строка «Округление» остаётся во внутреннем расчёте, но не выводится
в предварительном расчёте и заказ-наряде, включая PDF и повторную печать.
Итоговая сумма, округление и оплата мастеру рассчитываются по прежним правилам.

## Скидки

В блоке «Цена для клиента» задайте скидку в процентах или рублях.
Скидка применяется к сумме после округления, включая выезд, до целого рубля.
Она уменьшает прибыль компании, но не оплату мастеру за работу, штапики и дорогу.
Скидка сохраняется вместе с объектом и документом и видна в печати и PDF.

## Синхронизация через Яндекс Диск

1. На телефоне и компьютере откройте один и тот же адрес калькулятора.
2. Откройте блок «Яндекс Диск · синхронизация».
3. Нажмите «Получить доступ в Яндексе» и войдите в один и тот же аккаунт.
4. Разрешите доступ к папке приложения. Скопируйте токен с результата авторизации
   и вставьте непосредственно в поле калькулятора. Нажмите «Подключить Диск».
5. Повторите подключение на втором устройстве с тем же ClientID.

ClientID — открытая настройка приложения. Client Secret не используется.
Для личного приложения в Яндекс OAuth нужно только разрешение
`cloud_api:disk.app_folder`. Путь хранения: `app:/GlassBRON-sync-v1`.

Токен хранится только в браузере подключённого устройства. Он не включается
в выгрузку, PDF, файлы синхронизации или репозиторий. Чтобы отозвать доступ,
используйте список приложений в Яндекс ID; «Отключить» удаляет токен только
на текущем устройстве, сохраняя данные на устройстве и Диске.

Синхронизируются текущий расчёт и настройки, материалы, сохранённые объекты,
скидки и документы. Изменения отправляются после паузы около двух секунд;
при открытом калькуляторе проверка Диска выполняется каждые 30 секунд,
а также после возвращения в приложение и восстановления интернета.
На свежем устройстве используются данные Диска. Если на обоих устройствах
уже есть разные данные, они сохраняются как отдельные версии.

Без интернета данные остаются локально. Закрытое приложение не выполняет
фоновую синхронизацию. Пока пользователь редактирует поле, входящие данные
не заменяют отображаемый расчёт. Для немедленного обновления уберите фокус
с поля и нажмите «Синхронизировать сейчас».

Одновременные изменения одного объекта или расчёта сохраняются обе.
В блоке синхронизации можно скачать обе версии, затем явно выбрать нужную.
Перед применением входящих данных браузер сохраняет локальную резервную копию
в `glassbron-before-cloud-apply`; перед разрешением конфликта — его варианты
в `glassbron-cloud-last-conflict:<scope>`. Диск и локальные резервные копии
не заменяют периодическую ручную выгрузку данных.

Синхронизация требует HTTPS и современного браузера с Web Locks и Web Crypto.
Она не шифрует данные дополнительно: к файлам имеет доступ владелец Диска.
При переполнении хранилища, ошибке доступа или неверном файле калькулятор
показывает ошибку и не сообщает об успешной синхронизации.

## Структура

- `index.html` — интерфейс, расчёты, оптимизация раскроя, печать, PDF, локальные данные.
- `cloud-sync-core.js` — слияние версий с сохранением конфликтов и удалений.
- `cloud-data.js` — проверка данных и исключение посторонних полей из снимков.
- `yandex-disk.js` — работа с API Диска и проверка завершения загрузки.
- `cloud-sync.js` — подключение, автоматическая синхронизация, выбор версий.
- `sw.js`, `manifest.webmanifest`, иконки — установка и офлайн-режим.
- `html2pdf.bundle.min.js` — локальная библиотека PDF, загружается по запросу.

Каждый браузер пишет свой файл `device-<UUID>.json`. Слияние использует
причинную историю версий, а не время часов устройства. Web Locks сериализует
вкладки одного браузера. Секрет передаётся только API Яндекса в заголовке
Authorization; подписанные ссылки файлов используются без этого заголовка.

## Проверки

Нужен Node.js с `node:test`. Установка пакетов не требуется:

```sh
node --test tests/*.test.cjs
```

Проверяются скидки и независимость оплаты мастеру, сохранение документов,
слияние параллельных правок и удалений, работа двух устройств, офлайн-изменения,
отложенное применение во время ввода, ошибки API, проверка загрузки,
пагинация, направления передачи токена и исключение секретов из снимков.

Реальную авторизацию и обмен с Яндексом необходимо проверить после подключения
аккаунта: автоматические тесты используют имитацию API, не реальные токены.
